# 常见问题

| 现象 | 处理 |
|---|---|
| 找不到 node / Node 版本过低 | 安装 Node.js 22.13+，关闭并重开终端，再运行 `node --version` |
| PowerShell 阻止脚本 | 核对来源与内容，处理可信下载文件的解除锁定；组织策略联系管理员。脚本不改全局执行策略 |
| 找不到 Chrome／Edge | 安装浏览器，或在安装终端设置 `$env:CHROME_PATH='浏览器可执行文件的完整路径'` |
| 找不到 codex plugin | 选择 Local 供豆包使用；ChatGPT 需要支持本地插件的桌面环境及对应 CLI |
| 已安装但工具不可见 | 确认宿主启用插件／连接器，刷新连接或创建新会话；豆包选择“本地电脑” |
| 编辑器没有出现，仅工具文本成功 | 确认宿主同时支持 MCP Apps；检查卡片展开／侧栏。不要仅依赖模型描述 |
| `unknown MCP server` | 旧会话未加载插件，新建会话或刷新宿主连接 |
| `structured context is too deep` | 更新至 0.3.0+、更新豆包连接器路径、重新启用并创建新卡片 |
| `VERSION_CONFLICT` | 另一窗口保存了更新；先备份当前未保存内容，再关闭重复编辑器并重新打开最新草稿 |
| 保存中断后持续锁定 | 先关闭所有相关编辑器与 Node 进程、备份草稿；确认无人写入后手动处理该草稿的 `.json.lock`，不要删整个草稿目录 |
| PDF 空白／失败 | 检查浏览器路径和本机字体；先确认已保存，使用内置两种模板；大头像可能超过 6 MB |
| 下载按钮失败 | 生成预览与宿主下载是不同能力，确认客户端支持 MCP Apps 文件下载并查看宿主错误 |

提交问题时请提供 Windows、Node、宿主和插件版本、复现步骤、去除个人信息的错误信息。不要上传真实简历、访问凭据、.zresume、整个草稿目录或带个人聊天记录的截图。

## 豆包全屏编辑器跳转后空白

本机 0.4.0 验收完成后，在全屏 MCP Apps 编辑器通过 Ctrl+Shift+S 跳转插件页时，豆包导航到了缺少 `/chat` 的内部路由并显示空白。编辑、保存和 PDF 下载此前均成功；不要把空白当作草稿丢失。建议先退出编辑器全屏，再从侧栏点击“插件 · 技能 · 工作台”。若已空白，请先保存其他任务，再由用户重新打开豆包；本项目不会强制重启宿主。
